# Onboarding

## Use when
- A new user must complete setup or learn product-specific concepts before value is reachable.
- Initial configuration materially affects success.

## Avoid when
- The product is understandable without guided setup.
- A tour would explain obvious UI instead of enabling a real task.

## Core anatomy
- Clear outcome.
- Small number of essential setup steps.
- Progress where sequence matters.
- Skip/defer when safe.
- Return path.

## State and behavior
- First visit, partially complete, completed, skipped, blocked.

## Accessibility
- Do not depend on coach-mark positioning alone.
- Guidance should remain understandable with keyboard/screen-reader navigation.

## Responsive behavior
- Avoid tooltip tours that cannot fit reliably on small screens.

## Decision rules
- Onboarding should move the user toward first value, not showcase every feature.
- Defer optional configuration.
- Allow users to resume interrupted setup.
